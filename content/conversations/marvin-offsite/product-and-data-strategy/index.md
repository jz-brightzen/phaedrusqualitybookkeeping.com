## Summary

Product evolution toward a high-signal UX centered on **The Bin** and organizational memory. Mission framing: a “non-sucky workplace” — work feels meaningful when it is seen and valued; Marvin captures intent and can notify when a colleague praises someone’s work.

## The Bin

Mobile-first queue consolidating Email, Slack, Zendesk, Linear, etc. Interaction model nicknamed “Tinder for work”:

- Swipe left — archive / ignore  
- Swipe up — schedule (next free 30 min)  
- Swipe right — delegate or approve  

Adoption depends on eating existing queues — users won’t switch unless email and Slack can be processed inside the Bin.

## Memory & architecture

- Ian demoed stateful Marvin sandboxes vs typical AI platforms.
- Memories from meetings/Slack start personal; can be promoted to org knowledge.
- Access follows “keys to the castle” (calendar invite / Slack channel membership).
- Memory Browser (mind map or folder view) proposed for shared vs private knowledge.
- Default must stay **personal first** so proprietary data isn’t promoted by accident.

## ShipCom MVP

- Decorated data views: generic Marvin order viewer + ShipCom overlay (e.g. which robot holds a package).
- Data syndication via shared Marvin channels instead of Excel exports (e.g. anonymized shipping volumes to a tax partner).
